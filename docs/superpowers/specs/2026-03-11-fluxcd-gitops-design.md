# FluxCD GitOps for Tools Cluster

## Scope

FluxCD manages the tools k3s cluster only. It handles:
- All app manifests in `k8s/` (excluding `k8s/games/`)
- Helm releases: Hetzner CCM and CSI driver
- Secrets encrypted with SOPS + age

Game-servers cluster remains manually deployed.

## Access

FluxCD accesses the GitHub repo via a personal access token (stored as `FLUX_TOKEN_PAT`).

## Architecture

FluxCD runs in `flux-system` namespace, watches `main` branch, reconciles every 5 minutes.

```
GitHub repo (main branch)
    |
    v
FluxCD (in-cluster)
    ├── Kustomization: infrastructure/ (Helm repos, CCM, CSI)
    ├── Kustomization: secrets/ (SOPS-encrypted)
    ├── Kustomization: apps/
    │   ├── k8s/cloudflared/
    │   ├── k8s/telegram/
    │   ├── k8s/vpn/
    │   └── k8s/content/
    └── SOPS decryption (age key)
```

## Repo Structure Changes

New directories under `k8s/`:

```
k8s/
├── flux-system/           # Auto-generated by flux bootstrap
├── infrastructure/        # Helm releases + cluster-level resources
│   ├── helm-repos.yaml    # HelmRepository source
│   ├── hetzner-ccm.yaml   # HelmRelease
│   ├── hetzner-csi.yaml   # HelmRelease
│   └── kustomization.yaml
├── apps/                  # Kustomization CRs pointing to each app
│   ├── kustomization.yaml
│   ├── cloudflared.yaml
│   ├── telegram.yaml
│   ├── vpn.yaml
│   └── content.yaml
├── secrets/               # SOPS-encrypted secrets
│   ├── .sops.yaml
│   ├── ghcr-secret.yaml
│   ├── sleepy-bot-secrets.yaml
│   ├── booklore-db.yaml
│   ├── cf-tunnel-secret.yaml
│   └── hcloud-secret.yaml
```

Existing app directories (`cloudflared/`, `telegram/`, `vpn/`, `content/`) get a `kustomization.yaml` file listing their manifests.

## SOPS + Age

- Generate age keypair locally
- Private key stored as k8s secret in `flux-system` namespace (one-time manual)
- Public key referenced in `k8s/secrets/.sops.yaml`
- Secrets encrypted with `sops --encrypt` before committing
- FluxCD decrypts on apply

## Dependency Order

FluxCD Kustomizations use `dependsOn`:
1. infrastructure (Helm repos, CCM, CSI)
2. secrets (depends on infrastructure)
3. apps (depends on secrets + infrastructure)

## What Gets Removed

- `deploy-k8s` job from `deploy-tools-infra.yaml` (FluxCD handles Helm installs, secrets, CoreDNS)

## What Stays

- Terraform workflow for server provisioning
- `deploy-sleepy-notify.yaml` for Docker image builds (FluxCD handles rollout)
- Game-servers manual deployment

## Bootstrap

1. Install `flux` CLI
2. `flux bootstrap github` with PAT token
3. Create age key, store private in cluster
4. Encrypt existing secrets with SOPS
5. Add kustomization.yaml to each app directory
6. Add HelmRelease manifests
7. Push — FluxCD takes over
