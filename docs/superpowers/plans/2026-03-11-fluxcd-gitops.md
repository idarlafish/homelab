# FluxCD GitOps Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set up FluxCD on the tools k3s cluster to declaratively manage all app manifests, Helm releases, and SOPS-encrypted secrets from git.

**Architecture:** FluxCD bootstrapped via GitHub PAT, watching `main` branch path `k8s/`. Three layers of Kustomizations (infrastructure → secrets → apps) with dependency ordering. Existing plain YAML manifests stay unchanged, each directory gets a `kustomization.yaml` to make it Flux-compatible.

**Tech Stack:** FluxCD 2.7.5, SOPS 3.11.0, age 1.3.1, Kustomize, Helm

**Prerequisites:** `flux`, `sops`, `age` CLI tools (already installed). `FLUX_TOKEN_PAT` in `.env`. Tools cluster kubeconfig at `.kube/config`.

### Task 1: Generate age keypair for SOPS

**Files:**
- Create: `k8s/secrets/.sops.yaml`

- [ ] **Step 1: Generate age keypair**

```bash
age-keygen -o age.agekey
```

Save the output — it prints the public key (starts with `age1...`). Store `age.agekey` securely (do NOT commit it).

- [ ] **Step 2: Store private key in cluster**

```bash
source .env
export KUBECONFIG=.kube/config
kubectl create namespace flux-system --dry-run=client -o yaml | kubectl apply -f -
kubectl create secret generic sops-age \
  --namespace=flux-system \
  --from-file=age.agekey=age.agekey \
  --dry-run=client -o yaml | kubectl apply -f -
```

- [ ] **Step 3: Create .sops.yaml config**

Create `k8s/secrets/.sops.yaml` with the public key from step 1:

```yaml
creation_rules:
  - path_regex: .*\.yaml$
    encrypted_regex: ^(data|stringData)$
    age: >-
      <AGE_PUBLIC_KEY>
```

- [ ] **Step 4: Back up and delete local key file**

**IMPORTANT:** Back up `age.agekey` to a secure location (password manager, encrypted backup) BEFORE deleting. If the cluster is rebuilt, this key is needed to decrypt all SOPS secrets. Without it, encrypted secrets are unrecoverable.

```bash
# Back up to password manager or secure storage first, then:
rm age.agekey
```

- [ ] **Step 5: Commit**

```bash
git add k8s/secrets/.sops.yaml
git commit -m "feat: add SOPS age config for FluxCD secret encryption"
```

```yaml
metadata:
  name: hccm
  namespace: kube-system
spec:
  interval: 30m
  chart:
    spec:
      chart: hcloud-cloud-controller-manager
      sourceRef:
        kind: HelmRepository
        name: hcloud
        namespace: flux-system
  values:
    env:
      HCLOUD_TOKEN:
        valueFrom:
          secretKeyRef:
            name: hcloud
            key: token
      HCLOUD_NETWORK:
        valueFrom:
          secretKeyRef:
            name: hcloud
            key: network
```

Note: The CCM chart needs the hcloud token and network ID. These come from the `hcloud` secret in `kube-system` which is managed in the secrets layer. Verify the exact values key names match the chart's expectations after the first reconciliation — if the chart auto-detects the `hcloud` secret, simplify to `values: {}`.

- [ ] **Step 4: Create HelmRelease for CSI**

Create `k8s/infrastructure/hetzner-csi.yaml`:

```yaml
  namespace: kube-system
spec:
  interval: 30m
  chart:
    spec:
      chart: hcloud-csi
      sourceRef:
        kind: HelmRepository
        name: hcloud
```

- [ ] **Step 1: Export existing secrets from cluster**

Use `{ns}-{name}` filename pattern to avoid collisions (ghcr-secret exists in multiple namespaces).

```bash
export KUBECONFIG=.kube/config
mkdir -p k8s/secrets

for ns_secret in "telegram/ghcr-secret" "telegram/sleepy-bot-secrets" "booklore/booklore-db" "booklore/ghcr-secret" "cloudflared/cf-tunnel-secret" "kube-system/hcloud"; do
  ns=$(echo $ns_secret | cut -d/ -f1)
  name=$(echo $ns_secret | cut -d/ -f2)
  kubectl get secret $name -n $ns -o yaml | \
    kubectl neat > k8s/secrets/${ns}-${name}.yaml
done
```

This produces: `telegram-ghcr-secret.yaml`, `telegram-sleepy-bot-secrets.yaml`, `booklore-booklore-db.yaml`, `booklore-ghcr-secret.yaml`, `cloudflared-cf-tunnel-secret.yaml`, `kube-system-hcloud.yaml`.

Review each file to ensure it contains the correct secret data and has proper `metadata.namespace` set. Install `kubectl-neat` if not available: `kubectl krew install neat`.

If `kubectl neat` is not available, manually strip metadata fields (`creationTimestamp`, `resourceVersion`, `uid`, `managedFields`, `last-applied-configuration` annotation) from the exported YAML.

- [ ] **Step 2: Encrypt each secret with SOPS**

```bash
cd k8s/secrets
for f in telegram-ghcr-secret.yaml telegram-sleepy-bot-secrets.yaml booklore-booklore-db.yaml booklore-ghcr-secret.yaml cloudflared-cf-tunnel-secret.yaml kube-system-hcloud.yaml; do
  sops --encrypt --in-place $f
done
cd ../..
```

Verify encryption: `cat k8s/secrets/telegram-ghcr-secret.yaml` should show `ENC[AES256_GCM,...]` values.

- [ ] **Step 5: Create Flux Kustomization CR for secrets**

Create `k8s/flux-system/secrets.yaml`:

```yaml
---
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: secrets
  namespace: flux-system
spec:
  interval: 10m
  sourceRef:
    kind: GitRepository
    name: flux-system
  path: ./k8s/secrets
  prune: false
  wait: true
  timeout: 5m
  dependsOn:
    - name: infrastructure
  decryption:
    provider: sops
    secretRef:
      name: sops-age
```

Note: `prune: false` for secrets — we don't want FluxCD to delete secrets if they're temporarily removed from git.
